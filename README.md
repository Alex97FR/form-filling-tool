# 表格转交扩展

## 目标表读取卡住或返回 503 时

在“流程控制”页的“目标表诊断”中点击“诊断目标表”。它使用参数配置中当前填写的目标网址和分表名称，不需要源选区或模型 API Key。已有转交流程执行时，诊断按钮不可用；若是旧版控制台卡住，先关闭旧控制台，重新加载扩展后再打开控制台运行诊断。

诊断依次读取基本信息、保护及条件格式设置，然后对照单列前 20 行、A:BM 前 20 行和完整 A:BM 的读取结果。分表不足 20 行或 65 列时使用实际网格边界。每项读取最多等待 30 秒，请求之间至少间隔 1 秒；小范围数据读取失败后停止扩大范围，不自动重试。报告显示状态、耗时、已分配网格规模和非空单元格数量；“复制诊断结果”只复制诊断报告，不包含访问令牌、表格网址或单元格正文。

所有诊断请求都是只读 GET，不写入、清空或插行，也不调用 Gemini。读取通过不能证明具备写入/插行权限；发现不可编辑的保护范围也不代表本次写入区域一定受限。503 表示服务暂时不可用或请求/表格复杂度较高，单次诊断不能确定内部根因。正常转交流程的定位读取也增加了 30 秒超时和阶段耗时日志，插行前会记录具体阶段；写入请求没有添加自动重试。

本地检查：`node tests/target-diagnostics.test.js`（模拟 API，不访问真实表格）。

这是一个 Chrome/Edge Manifest V3 扩展：在 Google Sheets 的右键菜单中加入“转交表格”，并通过独立控制台显示流程进度和日志。

## 安装

1. 打开 `chrome://extensions` 或 `edge://extensions`。
2. 打开“开发者模式”，选择“加载已解压的扩展程序”，选中本目录。
3. 点击浏览器右上角的“表格转交”扩展图标，就会打开独立的自动化控制台，在其中填写目标表格网址和分表名称。
4. 在 Google Sheets 中选择要处理的数据行，按 `Ctrl+C`，再右键选择“转交表格”。

队伍 1（非 - 法）、队伍 3（非 - 英）、队伍 4（非 - 葡）和队伍 5（非 - 斯）按列位置转交。队伍 2（欧 - 法）使用内置列映射，包括 B→F、L/M 合并到目标 M，复制数据时无需包含表头行。

## 当前边界

程序使用 Sheets API 进行无格式写入，只处理选中的数据内容，不复制源表格式。

## 更新地址层级

1. 将最新地址 CSV 的三列同步到目标 Google 表格的“地区配置”分表：A=国家、B=省州或所属区域、C=市区或街区，首行为表头。
2. 在控制台保存对应的“地区配置分表”名称，点击“刷新地区配置”，立即读取更新，不必等待每日检查。
3. 再运行报告地址分析。W/X/Y 使用同一条配置记录的层级；支持双语国家名、斜杠别名、编号街区和罗马数字分区，遵循配置中的上下级关系。

队伍 4 和队伍 5 分别保存自己的地区配置分表名称。切换队伍后，在「智能补全」填写对应分表名并保存。两队每次转交都会重新读取所选分表的 A:C，首行 A 列填「国家」。

同名地址缺少上级信息时会记录待核实，不自动选第一条或最近地点。已有完整有效的 W/X/Y 路径保留；旧路径不符合新配置时，只有三列下拉项全部可用才一起纠正。CSV 是层级参考文件，扩展运行时读取 Google 表格，不直接读取本地 CSV。

本地回归检查：`node tests/address-matching.test.js`、`node tests/security.test.js`（仅使用 Node.js 标准库，不访问 API）。
提交到 master 或提交 PR 会执行语法、地址和安全检查；版本标签在检查通过后才打包发布。

## 可靠性

- 写入前预览，避免列错位或误操作。
- 断点续传会逐格核对原写入区域，补回缺失的数据。发现冲突时，先核对提示中的单元格，再决定是否覆盖并继续。
- 旧版失败行记录缺少目标表信息。扩展会保留这些行号，供人工核对。
- 自动过滤空行，保护目标表已有数据。
- Google 授权凭证过期时自动刷新。
- 支持批量查询、地址匹配和群组链接生成。
- 查询失败会记录日志，不影响其他数据处理。
- API Key 和本地配置只保存在本机，不上传到仓库。
- 在「参数配置 → 智能补全」选择 Gemini、OpenRouter 或 OpenAI，填写对应的 API Key 后点击「保存配置」。OpenRouter 可从五个预设免费模型中选择，默认使用 `nvidia/nemotron-3-ultra-550b-a55b:free`。旧配置中的其他 OpenRouter 模型会使用此默认值。OpenAI 默认使用 `gpt-4.1-mini`，也可以手动填写模型 ID。正常拆解和失败行重跑都使用已保存的服务。
- 导出配置不包含任何 API Key。换设备导入后，请重新填写密钥。
- Gemini 支持每行填写一个 API Key。每次运行按填写顺序循环使用密钥，收到 HTTP 429 时会尝试下一把，同一轮中每把密钥最多尝试一次。同一 Google Cloud 项目的密钥共享额度。
